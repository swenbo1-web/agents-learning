# 可视化知识审批（DSH）

用户在本机页面预览候选或管理员设置后作出决定。打开页面不批准候选、不开启模型；不替用户发布全部候选或点击「保存并开启」。

- 核对用户当前项目的绝对路径、宿主及知识目录；从本安装的 `runtime-release.json` 中读取 `python`、`runtime_directory`，或使用已生效 MCP 配置的同一固定入口。不要依赖终端 cwd、开发源码或其他项目的安装。沿用安装中的自定义 `ALP_CONFIG`。
- 使用已核实的实际路径运行：

  ```text
  <PYTHON> -B <RUNTIME>/scripts/learning.py --workspace <PROJECT_ABSOLUTE_PATH> --home <KNOWLEDGE_HOME> --host dsh browser --review --open --language zh-CN
  ```

  仅审批使用 `--review`，不加 `--admin-control`。用户要设置、开启或关闭管理员时加 `--admin-control`；可单独开启设置，也可同时开放审批。英文界面用 `--language en`。先检查该固定入口的 `browser --help` 是否支持所需参数；旧版本需要更新，不擅自改用其他源码。
- 保持临时本机服务在工具支持的持续终端或进程会话中运行；后台启动 Windows 进程时隐藏窗口。访问码、审批码、管理员控制码仅留在进程与页面内存，由 `--open` 直接打开完整启动链接；不回显含码输出，不写项目文档或持久日志。
- 管理员默认关闭，用户点击「保存并开启」才允许日常模型整理；页面浏览和知识审批不调用模型。`first` 默认绑定同项目、同宿主实例、同账户轮次首次有效根会话模型，后续对话保持，无观测等待不猜；用户也可选 `current`、`fixed` 或 CLI `default`。切换模型等待在途完成；界面关闭只阻止新调用，保留在途结果的原有处理边界。
- 次数和界面档位按项目独立计账、设置，同项目三个宿主合并统计。未配置项目继承配置默认值（100 次／UTC 日、每批最多 5 次／180 秒、运行器 600 秒；旧配置明确 5 次则仍继承 5 次）。`ALP_HOME` 全局总保护及共享并发另行显示；全局保护可阻止有项目余量的新调用。缺少项目字段时报告不可用，不把全局数代替项目数；启动尝试不等于有效审核，未知 token 用量不当成零。
- `admin-drain` 只在有限时长内连续处理日常待办，遇空、未知、错误或额度不足停止，后续受支持事件可继续有效待办；不安装常驻服务、不自动重试未知调用。历史吸收仍独立授权；当前 `main` 的显式历史运行默认最多 10 次调用／600 秒，开始或续跑前先说明预算，用户明确设为 2 次等较小值时遵守。开启管理员不启动或恢复历史，不代表处理全部历史。
- 用户查看候选正文、适用条件、限制、来源、证据等级及发布检查后，在页面选择单条或固定清单批准并发布、拒绝或暂缓。按钮由程序处理，不额外调用模型；发布结果以逐条回执为准。
- `reported` 资料发布后不升级为已验证；候选、来源或版本变化时刷新详情并重新选择，不覆盖检查或规避冲突。知识批准不授予工具执行权限，不启动历史吸收或管理员模型，也不撤销正式知识。
- DSH 的 `learning_browser` 原生工具及 `/learning-browser` 仍只读。审批使用上方 `browser --review`；仅查看正式知识时使用 `learning-browser`。
