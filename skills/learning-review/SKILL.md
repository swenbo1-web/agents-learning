# 可视化知识审批

在当前项目打开审批台或管理员设置，让用户在页面完成决定。打开页面不批准候选、不开启模型；不替用户批量发布或点击「保存并开启」。

## 打开当前安装的审批台

- 核对当前用户要管理的项目绝对路径、宿主及知识数据目录。读取当前安装的 `runtime-release.json` 中的 `python`、`runtime_directory`，或已生效的 MCP 配置中同一固定运行入口；使用对应的 `scripts/learning.py`。不要依赖终端 cwd、开发源码、其他项目的安装或猜测默认知识目录。自定义 `ALP_CONFIG` 时沿用当前安装配置。
- 使用已安装的实际解释器和固定入口运行，以下 `<...>` 代表已核实的实际值：

  ```text
  <PYTHON> -B <RUNTIME>/scripts/learning.py --workspace <PROJECT_ABSOLUTE_PATH> --home <KNOWLEDGE_HOME> --host codex browser --review --open --language zh-CN
  ```

  仅审批使用 `--review`，不加 `--admin-control`。用户要设置、开启或关闭管理员时增加 `--admin-control`；只管理设置可省略 `--review`，两者也可同时开启。Antigravity／DSH 分别使用 `--host antigravity`／`--host dsh`；英文界面用 `--language en`。先核对该固定入口的 `browser --help` 是否支持所需参数；旧安装需要更新，不切换源码或绕过审批。
- 保持临时本机服务运行。使用工具支持的持续终端或进程会话；后台启动 Windows 进程时隐藏窗口。访问码、审批码和管理员控制码只保留在进程及页面内存，完整启动链接由 `--open` 直接打开；不回显或保存含访问码的启动输出，不写项目文档或持久日志。

## 管理员设置

- 管理员默认关闭；用户在界面选择模型和预算，点击「保存并开启」才允许日常整理。页面浏览和知识审批不调用模型；开启后的后台整理会使用所选平台模型额度。
- 默认 `first` 绑定同项目、同宿主实例、同账户轮次的首次有效根会话模型，后续对话不改变该选择；没有真实模型观察时等待，不猜模型。也可由用户选择 `current`、`fixed` 或 CLI `default`。切换模型需等在途审核完成；界面关闭管理员只阻止新调用，已在途结果按原边界处理。
- 调用次数和界面中的日上限、每批次数及运行时长按项目独立统计、设置，同项目三个宿主合并计账。未配置项目继承配置默认值（100 次／UTC 日、每批最多 5 次／180 秒、运行器 600 秒；旧配置明确 5 次则仍继承 5 次）。另行显示的 `ALP_HOME` 总保护和共享并发仍限制全部项目。区分项目额度不足与全局保护触发；缺少项目统计时报告不可用，不用全局数代替。有效结论、启动尝试和 token 用量分别说明，未上报用量保持未知。
- `admin-drain` 只在有限时长内连续处理日常待办小批；空队列、未知调用、错误或额度不足即停止，后续受支持事件可以再次推进有效待办。它不是退出软件后持续运行的服务，不自动重试未知调用。历史吸收仍独立授权；当前 `main` 的显式历史运行默认最多 10 次调用／600 秒，开始或续跑前说明本次预算，用户明确指定 2 次等较小值时遵守其选择。开启管理员不启动或恢复历史，也不代表完成全部历史。

首次界面开启管理员会建议分级自动发布；用户可关闭或选择仅验证解法，已有设置保留。历史参考发布需逐次批次确认；reported 不变为验证结论。旧知识有未解决反例时暂停自动注入，管理员只提出修订／撤销建议，经明确治理入口执行；已有待批候选不追溯批准。

## 在页面完成决定

- 提示用户查看候选正文、适用条件、限制、证据等级、来源和发布检查，然后选择单条或固定清单进行操作。页面操作由程序执行，不增加模型调用。
- `reported` 历史事实发布后仍是 `reported`；“批准发布”不等于当前测试通过或用户已验收项目行为。来源变化、版本冲突或候选失效时，刷新详情后重新选择；不覆盖检查结果或重复提交新的批准来规避冲突。
- 只依据程序回执说明每条实际结果；打开页面、点击按钮或工具退出成功都不能代替发布回执。知识审批不批准工具执行、不启动历史吸收或管理员模型，也不撤销正式知识；管理员调用必须经设置页独立开启。
- 仅需要查看正式知识时使用只读 `learning-browser`，不启动审批模式。
